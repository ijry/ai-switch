# SaaS 日志驱动实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans task-by-task. Track steps with checkboxes.

**Goal:** 实现可切换内存/Redis 队列与文件/PostgreSQL 存储，不把请求明细写 SQLite。

**Architecture:** 独立 LogRuntime 协调消费者；队列与存储均通过接口替换，四种组合有效。

**Tech Stack:** Tokio、async-trait、serde、chrono、SQLx PostgreSQL、Redis。

**Spec:** `docs/superpowers/specs/2026-09-07-saas-plugin-design.md` 第 9 节。

## Global Constraints

- 继承总计划；本子项目只写 `src-tauri/src/saas/logs/`；依赖修改向集成者报告，不改宿主代理。
- 日志无 token/Cookie/提示词；默认 home 下 `ai-switch/logs`；唯一 target-codex。
- 运行中重试，强制结束的内存未落盘丢失窗口不隐瞒；账务不依赖队列。

## Task 1: DTO、文件存储与查询

**Files:** `logs/mod.rs`、`logs/types.rs`、`logs/file.rs`、`logs/tests.rs`。

**Interfaces:** `LogRecord` camelCase 字段含 requestId、userId、keyId、groupId、platform、model、createdAt、durationMs、status、inputTokens、cacheReadTokens、cacheWriteTokens、outputTokens、amountUsdMicros、settlementStatus、errorCode。`LogQuery` 含 from/to、用户与 Key/分组/模型/状态过滤及页码。`LogStore` 异步 append_batch、query、retention。

- [ ] 文件追加、日期滚动、归属、重复 ID、坏行、路径限制失败测试。

```rust
assert!(root.join("2026-09-07/09.log").is_file());
assert!(result.items.iter().all(|row| row.user_id == owner));
assert_eq!(result.items.iter().filter(|row| row.request_id == duplicate_id).count(), 1);
```

- [ ] `cargo test --lib saas::logs` 观察失败。
- [ ] 串行 JSONL 写入，限制页大小/时间跨度；时间戳 UTC 与路径本地时钟分离；保留期仅清理规范文件。
- [ ] 转绿，不用整个无限文件历史装入内存。

## Task 2: 有界内存队列与后台生命周期

**Files:** `logs/runtime.rs`、`logs/memory.rs`、`logs/tests.rs`。

**Interfaces:** `LogRuntime: Clone + Default`；`configure(LogConfig)`、`enqueue(LogRecord)`、`query(LogQuery)`、`status()`、`shutdown()` 为 async Result。LogConfig 独立 serde 类型供 SaasConfig 嵌入。

- [ ] 写满队列背压、存储失败重试、重新配置排空、正常停机测试。

```rust

runtime.shutdown().await.unwrap();
assert_eq!(store.query(query).await.unwrap().items.len(), 1);
```

- [ ] 跑定向测试；实现条数/字节上限、有限等待、退避、脱敏状态、切换排空。
- [ ] 默认配置不连接外部服务；文档明示内存丢失窗口。

## Task 3: Redis 与 PostgreSQL 真驱动

**Files:** `logs/redis.rs`、`logs/postgres.rs`、`logs/integration_tests.rs`。

**Interfaces:** 同一 LogQueue/LogStore 语义；Redis 流命名带 instanceId，成功存储才 ACK；PG 表 `saas_request_logs` 唯一 request_id，schema 元数据也用 saas 前缀。

- [ ] 配置失败、无权限、重复写入、隔离查询测试先失败。
- [ ] 实现 Redis pending 恢复和批次提交/确认，PG 参数化批次插入、分页、清理；不能只是枚举。
- [ ] 无真实服务的测试显式标记需环境，给出服务参数名称和运行命令；不得模拟通过真实验证。
- [ ] 真实服务可用时跑集成；提交文件，报告接口与依赖需求。
