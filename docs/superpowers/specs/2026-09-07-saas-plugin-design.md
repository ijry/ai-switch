# SaaS 内置插件与双入口设计

日期：2026-09-07

状态：对话方案已确认，书面设计待审阅。本文不是功能已经实现的声明。

## 1. 目标与已确认决策

加入可启停、可独立演进的 SaaS 子系统，使现有管理端与普通用户站点共存。本次交付完整功能，不缩减为只有页面或入口分流的 MVP。

| 事项 | 已确认方案 |
| --- | --- |
| 技术栈 | 沿用 Rust、React；复刻本地 pro-api 用户页，不引入 Vue 运行时 |
| Web 入口 | `/ai-switch-admin` 固定为管理入口；关闭 SaaS 时 `/` 临时跳转管理入口，开启时展示用户站点 |
| 桌面入口 | 始终打开管理界面，不因开启 SaaS 变成用户站点 |
| 用户认证 | 仅 GitHub OAuth；GitHub 账号创建至少满 365 天；注册可单独关闭 |
| 管理员认证 | 复用现有 Web Service 主 bearer token；桌面使用受信任命令适配器 |
| 用户凭证 | 独立浏览器 session 和 API Key，不复用管理员或移动配对 token |
| API Key 与分组 | 一个 API Key 固定绑定一个分组；需要其他分组时另建 Key |
| 分组 | Codex、Claude 两类端点；默认/自定义批次多选；模型白名单、输入/缓存/输出价格和倍率 |
| 充值 | 人工申请、管理员审核、兑换码；本次不接在线支付网关 |
| 余额与价格 | 美元定点余额；人民币充值按配置汇率换算，订单保存换算快照 |
| 业务数据 | SaaS 业务表统一 `saas_` 前缀 |
| 日志队列 | 默认有界进程内存队列，可配置外部 Redis；默认实现不声称兼容 Redis 协议 |
| 日志存储 | 默认文件系统，同时实现 PostgreSQL 驱动；请求明细不进 SQLite |
| 默认日志路径 | `~/ai-switch/logs/yyyy-mm-dd/hh.log`，不是现有 `~/.ai-switch/logs` |
| 可靠性 | 正常停机排空；允许崩溃丢失尚未落盘的内存日志；已提交账务独立持久化 |

## 2. 当前实现与约束

- `src-tauri/tauri.conf.json` 的 `frontendDist` 为 `../dist`，桌面开发入口是 Vite 的 `127.0.0.1:1420`。生产版使用打包资源，不要求先启动 HTTP 管理服务。
- `src-tauri/src/web/static_assets.rs` 对 `/` 返回 `index.html`，无扩展名客户端路径也使用 SPA fallback。
- `src/App.tsx` 用组件状态切换管理页面，目前没有独立的用户站点入口。
- `src-tauri/src/web/router.rs` 支持管理 Web 服务与独立服务器共享监听器；后者把模型 API 分流到现有代理。
- 管理 API 已区分主 token 与低权限移动配对 token，SaaS 管理操作只能接受前者。
- 现有代理可用本地代理 Key 或 `x-ai-switch-platform` 解析平台。平台提示本身不能成为公开 SaaS 入口的授权凭据。
- 复用现有流式转发、协议适配、账号池、重试和冷却流程，不复制第二份协议代理。
- 现有 `usage_events` 保存逐请求数据，SaaS 请求必须避开该写入路径。
- 默认批次对应 `batch_id IS NULL`，现有筛选标识为 `__single__`；自定义批次按 ID 关联，不按名称匹配。
- 参考项目是 `D:\Repos\xyito\open\pro-api\web\user`。首页含余额、今日/月度用量、最近请求和快速接入；充值页使用人工审核。

保留当前 `task/164` 工作树与分支，不切换到 `main`，不新建工作树，不合并、变基或推送基分支。

## 3. 子项目与模块边界

按五个有独立验收面的子项目组织实施，五项共同构成本次完整交付：

1. 入口与插件生命周期：分流、配置、管理菜单、运行时启停。
2. 身份与用户资源：OAuth、会话、用户、Key、数据隔离。
3. 分组与账务代理：账号范围、模型价格、余额、充值、兑换、真实请求计量。
4. 请求日志：内存/Redis 队列、文件/PostgreSQL 存储、查询、故障可观测性。
5. 完整用户站点与管理界面：真实 API 对接、桌面/Web 验收。

### 3.1 建议目录

```text
src/saas/
  entry/          用户站点启动、路由与模式判断
  api/            公开、用户、管理员客户端与类型
  components/     SaaS 布局和通用组件
  user/           首页、用量、Key、充值、兑换、个人信息
  admin/          用户、分组、账务、充值、兑换码、日志
  settings/       设置页中的插件配置
  i18n/           SaaS 文案

src-tauri/src/saas/
  mod.rs          对宿主的最小接口
  config/         校验、密钥引用和运行时快照
  auth/           GitHub、state、session、权限
  domain/         用户、分组、Key、定价与交易规则
  repository/     业务数据访问
  billing/        预占、结算、充值、兑换、对账
  proxy/          受信任请求上下文、范围过滤、完成回调
  logs/           队列、存储、查询、后台消费者
  transport/      HTTP 与桌面命令适配器
  migrations/     SaaS 迁移 SQL
```

这是职责划分，不要求预建空文件。不能用单个总服务包揽认证、财务和日志。

### 3.2 宿主接口

- 宿主提供路径、数据库连接、现有代理、管理员权限与 UI 挂载点；SaaS 管理自己的迁移、配置、认证、业务规则与后台任务。
- 桌面命令和 HTTP handler 调用同一业务服务，不分别实现规则。
- 代理接收服务端构造的上下文：用户、Key、分组、允许账号、模型、价格快照、结算 ID 与记录策略。
- 重试只在允许账号范围内进行；任何兜底都不能扩大到整个宿主池。
- 非 SaaS 请求保持原行为；SaaS 请求使用独立账务、聚合统计和日志完成回调。
- SaaS 完成回调不调用宿主记录完整请求/响应的实时日志分支；账号健康和必要聚合继续更新，不能以复用代理为由额外保存提示词或上游秘密。
- 本次不建立动态加载二进制、脚本执行、插件市场或完整第三方插件 ABI。

## 4. 入口路由与模式切换

### 4.1 路由契约

| 路径或运行环境 | SaaS 关闭 | SaaS 开启 |
| --- | --- | --- |
| 桌面内置页面 | 管理界面 | 管理界面 |
| Web `/` | `302` 到 `/ai-switch-admin` | 用户首页；未登录显示 GitHub 登录入口 |
| Web `/index.html` | 按根入口处理 | 按根入口处理，不能绕过站点选择 |
| `/ai-switch-admin`、其管理子路径 | 管理 SPA 与原有鉴权 | 同左 |
| `/usage`、`/api-keys`、`/recharge`、`/redeem`、`/profile` | 临时跳转管理入口 | 用户 SPA，登录后显示个人数据 |
| `/login` | 临时跳转管理入口 | GitHub 登录页 |
| `/api/saas/public/config` | 只返回脱敏站点状态 | 只返回脱敏站点状态 |
| `/api/saas/auth/*`、`/api/saas/user/*` | 返回不可用，不进入 HTML fallback | 对应认证或用户 API |
| SaaS 管理 API/桌面命令 | 主 token/桌面权限保护，可配置与重新开启 | 同左 |
| 静态资源 | 正常提供，缺失返回 404 | 同左 |

- 原有 `/api/:command` 管理契约、WebSocket 和移动配对接口不因页面路径迁移而整体改名。
- 独立服务器沿用共享监听器；桌面开启 Web Service 时，在其监听器提供用户站点和同源 SaaS 模型入口，底层复用代理状态，不要求远程浏览器访问桌面的另一个 loopback 端口。
- SaaS HTTP 分成 `/api/saas/public`、`/api/saas/auth`、`/api/saas/user`、`/api/saas/admin`，显式注册并分别鉴权。
- 根重定向、公开配置和鉴权响应使用 `Cache-Control: no-store`，不用永久重定向，避免开启后浏览器仍跳管理端。
- 开启后未知页面显示用户侧 404，不能因 SPA fallback 意外展示管理启动页；未知 API 返回 JSON 404，不返回 `index.html`。
- 前端先判断桌面环境，再按浏览器路径选择管理或用户入口；用户 OAuth session 不能自动解锁管理端。
- 构建保留根级绝对资源路径，管理子路径刷新仍可加载 CSS、JS 和图片。
- 公开配置只含启用/注册状态、站点展示信息和登录可用状态，不返回秘密、连接地址或管理员 token。
- Vite 开发代理不能给 SaaS 用户/公开请求自动附加管理员 token；管理与用户调用使用不同的客户端拦截策略。

### 4.2 生命周期

- 默认关闭，不主动连接 Redis、PostgreSQL 或 GitHub。
- 开启前校验 OAuth、公开地址、账务配置和所选日志驱动；失败不发布半启用状态。
- 启停和配置更新串行协调；前端刷新菜单与入口，已打开的旧页面也能处理服务端拒绝。
- 关闭后拒绝新的 OAuth、用户操作与 SaaS 推理；已接收请求完成结算，消费者排空已接收日志后停止。
- 关闭不删除用户、余额、Key、分组、交易或日志。重新开启保留业务数据，但旧浏览器会话需要重新登录。
- 驱动变更先验证新驱动，再切换新请求；旧消费者排空自己的记录，不能静默丢弃旧请求。
- 切换不自动迁移历史日志；界面说明当前查询驱动和历史位置，原数据不删除。
- 驱动故障或模式查询失败显示错误，不能自动退回未鉴权的管理页面。

## 5. GitHub 身份与权限

### 5.1 OAuth

- 配置 client ID、client secret、站点公开 URL；回调固定为公开 URL 下的 `/api/saas/auth/github/callback`。
- 服务端生成高熵 state 与 PKCE S256 verifier/challenge，state 绑定发起浏览器并短期过期。
- 回调验证浏览器绑定、state 一次性消费和有效期后才交换 code；不能仅凭 URL 中的有效 state 接受其他浏览器登录。
- 从 GitHub 已认证用户接口取得稳定 ID、用户名、头像和 `created_at`，不信任浏览器提交的账号年龄。
- 使用服务端 UTC，要求 `now - created_at >= 365 天`；缺失/未来创建时间或 GitHub 失败均拒绝，不创建半完成用户。
- GitHub ID 是唯一身份，用户名变更不创建新用户。不实现邮箱密码注册、用户输入 GitHub token 登录或自行绑定管理员角色。
- 新用户同时满足插件开启、注册开启和年龄条件；关闭注册只禁止首次开户，已有合格用户仍可登录。
- 已封禁用户拒绝登录；撤销会话与 Key 的检查在服务端完成，不能只隐藏按钮。
- 不保留不必要的 GitHub access token；建立本站会话后释放读取身份所用临时 token。
- 回调后的跳转只允许本站已知用户路径，禁止任意 URL、协议相对地址和管理路径跳转参数。

### 5.2 Session、CSRF 与秘密

- 浏览器使用随机不透明 session，服务端只保存摘要。Cookie 为 HttpOnly、SameSite=Lax、Path=/；生产 HTTPS 使用 Secure。
- 非 loopback 公开站点必须使用 HTTPS；开发 HTTP 例外只限显式 loopback，不信任任意转发头自动判定安全连接。
- 用户写操作要求本站 Origin 与会话绑定 CSRF token；敏感响应不缓存，不能沿用允许任意来源的 CORS 配置携带用户 Cookie。
- 登录状态、OAuth state、Key 有数量/时间限制；认证、兑换和充值创建接口限流。
- 主 token 才能授权 SaaS 管理；移动配对 token、用户 session 和用户 Key 均不能调用管理 API。
- 从 session 推导用户 ID；列表、详情、导出、修改和日志查询都附带归属条件，不能用客户端用户 ID 作为授权依据。
- OAuth secret、Redis/PostgreSQL 密码通过专用秘密访问层管理：桌面可用现有 SecretStore，独立服务器支持环境变量或限制访问权限的私有配置存储。
- 管理界面只返回“已配置”和脱敏连接信息，未更改的秘密字段保留原值；用户 API 不提供明文秘密读取。

## 6. 分组、模型与 API Key

### 6.1 分组

- 分组含名称、启用状态、端点 `codex` 或 `claude`、倍率、默认批次选择、自定义批次 ID 集合、模型价格和请求限制。
- 默认批次复用 `batch_id IS NULL`；自定义批次按 ID 关联，改名不失效。
- 可用账号是“允许批次、平台匹配、已入现有账号池、未禁用/归档”与现有模型能力筛选的交集。
- 新账号进入已选批次后可参与后续请求；移出、禁用或归档后不再接收新请求。已接收请求保留授权快照。
- 批次删除或筛选为空使分组不可提供请求，绝不把空集合解释成所有账号。
- 所有启用分组可由用户创建 Key 时选择；本次不新增套餐、组织、多级代理或隐藏的用户分组授权体系。
- 管理员改价、改倍率、改批次或禁用后对新请求生效；已接收请求使用快照。

### 6.2 模型与价格

- 展示该端点/批次可用的客户端模型；已选但暂时无账号支持的模型保留配置并提示不可用。
- 每个允许模型明确配置输入、缓存、输出单价，单位美元/百万 token。允许显式零价，不把缺失价格当零。
- 倍率为正数定点值；价格非负，拒绝 NaN、无穷值、负数和溢出。
- 模型、别名、账号前缀模型名最终都要符合分组白名单，不能利用宿主模型语法绕过授权。
- `/v1/models` 只返回所属分组允许且可提供的模型，不返回全池模型或内部账号名称。
- 设每请求输出上限、超时和用户/Key 并发上限，防止无限生成与无界资源占用。

### 6.3 API Key

- 高熵 Key 使用独立 `sk-saas-` 前缀；明文只在创建/轮换时展示一次，数据库保存摘要、展示前缀/末尾、归属与权限。
- 支持创建、命名、停用、删除、轮换、过期时间与消费额度限制。
- 固定绑定一个分组，不能通过请求参数切换；换组需创建新的 Key。
- 删除使用保留历史引用的撤销方式，不破坏交易与日志关联；禁用和轮换立即影响新请求。
- 用户 Key 不授予浏览器管理权限，用户 session 也不充当模型 API Key。

## 7. 代理接入与美元账务

### 7.1 安全入口

- 复用现有共享端口与代理，支持 Codex Responses/Chat Completions、Claude Messages 的普通和 SSE 响应。
- 仅开放具有授权、归属检查和结算能力的 SaaS 模型路径；未覆盖的异步资源、文件、Realtime 或模型管理路径明确拒绝，不退回无限制宿主代理。
- 开启 SaaS 的公开模型入口先验凭证，再解析平台；`x-ai-switch-platform` 不能单独授权请求。
- 有效的既有宿主代理 Key 仍走宿主策略；无效/过期/撤销的 SaaS Key 不得降级为平台请求头授权。
- 服务端移除或覆盖客户端平台/账号提示，构造受信任上下文。仅替换成管理员 token 后调用旧代理不可接受。

### 7.2 金额与 token

- 美元余额使用整数微美元；人民币使用整数分；配置小数用定点解析，中间计算用足够宽的整数。
- 价格、倍率和人民币/美元汇率保存可复现快照；前端可显示小数，但不以 JavaScript 浮点运算决定扣款。
- 输入指未缓存输入；缓存指缓存读取。Claude 缓存写入默认按输入价计费，界面明确说明。
- OpenAI 总输入包含缓存时先扣除缓存读取部分；Claude 单列缓存读取/写入分别归类，不能将宿主合并 cache 字段重复收费。
- 费用为 `(未缓存输入 × 输入价 + 缓存读取 × 缓存价 + 输出 × 输出价) × 分组倍率 / 1,000,000`；最终微美元金额向上取整，零价请求保持零。
- 上游成本不能覆盖管理员设定的 SaaS 售价。

### 7.3 请求与结算状态机

1. 验证插件、用户、Key、分组、模型、限额，获取价格快照。
2. 检查日志接收能力，申请受限并发/日志名额；不可接收时在转发前返回 429 或 503。
3. 生成唯一结算 ID，事务内预占余额和 Key 额度；并发请求不能重复使用同一份可用余额。
4. 在允许账号范围内使用现有重试、协议适配和流式转发。
5. 请求结束、流结束或客户端断连进入统一完成流程；内部重试不重复计费。
6. 同一数据库事务写唯一流水、更新余额/预占/Key 消费和小时聚合后提交。
7. 脱敏请求记录交给日志队列；日志是否落盘不决定该笔账是否已经提交。

结算规则：

- 正常完成按实际 usage 扣费、释放剩余预占；转发前失败或明确没有可计费用量的失败释放预占。
- 不缓存整个 SSE 再交付；断连也触发有界完成任务，不能因响应对象丢弃而漏结算。
- 预占结合输入、输出上限和模型价格估算，不是无限信用；实耗超过预占时原子补扣。余额不足记录真实欠费，并拒绝后续付费调用，不能将差额静默免费处理。
- 限制 token、时长和并发，使异常超支受限；界面区分余额、冻结金额、可用金额和欠费。
- usage 缺失、截断后无法确认用量或崩溃遗留未决请求进入“待核对”，不捏造零费用，不在重启时无条件退款。
- 管理端显示待核对金额，允许人工补结算/退款，记录理由、来源请求和操作者；同一请求只允许一个有效最终结算。
- 已最终结算 ID 的完成回调重放，不再扣费、累计用量或限额消费。

### 7.4 充值与兑换

- 人民币充值申请分待审核、已通过、已拒绝、已取消。用户只能取消自己的待审核订单，不能改金额后沿用旧审核。
- 创建时固化人民币金额、汇率和预计到账微美元；换算向下取整，之后改汇率不改变待审核订单。
- 审核通过与余额入账在同一事务；重复点击/重放只到账一次。拒绝不入账，保留原因。
- 兑换码含固定到账微美元、过期时间、状态和使用归属；高熵明文只在生成时导出，存摘要用于兑换。
- 兑换、次数改变和入账同一事务完成；同一码并发兑换只能有一个成功者。
- 管理员可批量生成、停用、查询兑换状态；用户只能看到自己的兑换结果，不能读取其他用户或未使用兑换码。
- 财务调整使用有理由、可追溯的账务操作，不能直接编辑余额绕过流水。

## 8. 业务数据库

SaaS 使用独立迁移集，宿主迁移完成后执行；业务共用现有 SQLite 连接，不混用宿主迁移版本表。

迁移按版本校验 checksum 并事务执行，失败回滚且不启动 SaaS。元数据使用下面定义的专属表，不能直接启用另一个默认写入 `_sqlx_migrations` 的迁移器与宿主混用。

| 表 | 职责 |
| --- | --- |
| `saas_schema_migrations` | SaaS 迁移版本、校验与时间，避免新增无前缀的迁移表 |
| `saas_settings` | 非敏感配置、实例 ID、配置版本、秘密引用 |
| `saas_users` | GitHub 唯一身份、状态、美元余额与冻结金额 |
| `saas_oauth_states` | 浏览器绑定的一次性 OAuth 状态，短期有效并清理 |
| `saas_sessions` | session 摘要、用户、失效时间和撤销状态 |
| `saas_groups` | 端点、名称、状态、默认批次选择、倍率、限制 |
| `saas_group_batches` | 自定义批次 ID 关联 |
| `saas_group_models` | 模型白名单、三类价格、版本、限制 |
| `saas_api_keys` | Key 摘要、归属、固定分组、状态、限额、消费 |
| `saas_billing_reservations` | 未完成/待核对预占和必要价格快照，不存正文 |
| `saas_wallet_ledger` | 不可变的必要账务流水、金额、来源、幂等标识 |
| `saas_recharge_orders` | 人工申请、汇率快照、审核状态 |
| `saas_redeem_codes` | 兑换码摘要、金额、失效时间、使用归属 |
| `saas_usage_hourly` | 用户、Key、分组、模型、UTC 小时聚合的次数、token、费用 |
| `saas_admin_audit` | 配置、审核、封禁、人工账务操作的脱敏审计 |

- 必要账务流水可逐请求存在，但只用于金额核对和幂等，不能塞入 token 明细、HTTP 内容或提示词来变相保存请求日志。
- 请求明细只在日志驱动中；不新增 SQLite `saas_request_logs`，不让 SaaS 请求写入宿主 `usage_events`。
- 用户/Key/分组停用或软删除以保留历史引用，不能级联删除交易链。
- 金额、外键、唯一身份、唯一结算来源、兑换唯一性同时使用数据库约束和业务校验。
- 纳入宿主用户数据识别与备份，避免含 SaaS 用户/余额的数据库被误判为空库。
- 首次迁移仅新增默认关闭的 SaaS 结构，不重写账号、宿主代理 Key 或旧统计。

## 9. 请求日志驱动

### 9.1 队列与存储解耦

- `LogQueue` 管理容量、发送、接收、确认、重试、停止；实现内存与 Redis。
- `LogStore` 管理批量写入、用户范围分页、管理员查询、保留期清理；实现文件与 PostgreSQL。
- 四种组合都有效，不能把 Redis 强制绑定 PostgreSQL。
- 对仍在运行的进程或可恢复队列，使用至少一次的重试投递；记录带全局请求 ID，查询去重，PostgreSQL 用唯一约束去重。日志不用于再次扣账。
- 内存未落盘记录在进程崩溃时没有端到端至少一次保证；账务已提交但尚未成功入队的窗口也可能缺日志，不能因选 Redis 就隐去这个边界。

### 9.2 默认文件系统

- 默认是 home 下 `ai-switch/logs`，与宿主 `~/.ai-switch` 分离；设置可配置绝对目录。
- 按服务端本地日期/小时追加 `yyyy-mm-dd/hh.log`，每行一个 UTF-8 JSON；记录时间保存 UTC 和偏移。
- 记录含 schema 版本、请求 ID、用户/Key/分组引用、端点、客户端模型、时间、耗时、状态、规范化 token、美元费用、结算状态和安全错误码。
- 不记录 Key、session、Authorization、Cookie、OAuth code/secret、完整请求/响应正文或完整提示词。
- 串行 writer 追加，一个业务实例只有一个活动写入者；只读取服务端生成的日期/小时路径，不把用户输入拼成任意磁盘路径。
- 查询必须有时间窗口，默认最近 24 小时，单次最多 31 天，单页最多 100 条；支持用户、Key、分组、模型、状态过滤。
- 用户查询强制归属过滤并移除内部账号信息；管理员独立鉴权。坏行/尾部未写完行计数告警，不暴露原始内容。
- 默认保留 30 天，可配置天数或明确关闭自动清理；只清理已校验 SaaS 根目录内规范日期文件，不清理宿主操作日志。

### 9.3 内存与 Redis

- 内存队列同时限制条数和总字节，入队名额与推理接收协调，不能无限增长。
- 暂时故障退避重试；持续堵塞使新推理在转发前失败，不静默丢弃健康进程的已接收日志。
- 正常关闭停止接收并等待排空，超过停机等待期限报告剩余数量；强制结束/断电允许丢失内存未落盘日志，此边界已确认。
- Redis 使用可确认/重放的流或可靠队列，不能使用“弹出后未落库就永久删除”的语义。
- 命名含稳定实例 ID，例如 `ai-switch:saas:<instance-id>:request-logs`，避免不同站点混流。
- 存储成功才确认；消费者重启恢复未确认记录，不裁剪未处理数据。
- Redis 断电耐久度依赖部署者的持久化设置，选择 Redis 不自动获得零丢失承诺。

### 9.4 PostgreSQL

- 配置独立连接、连接池上限和 TLS；凭证不返回浏览器、不写日志。
- 目标表 `saas_request_logs`，迁移元数据也用 SaaS 前缀；请求 ID 唯一，索引用户/时间、Key/时间和管理时间查询。
- 后台批次事务插入，重复 ID 幂等忽略；提交后才确认队列。
- 查询契约与文件一致，参数化并限范围；余额仍在 SQLite，选择该驱动不迁移业务数据库。
- 启用时验证连接和 schema 权限；不可用明确报错，不假装配置生效、实际写回 SQLite。
- Redis/PostgreSQL 不成为桌面默认运行的外部依赖。

### 9.5 可观测性与规模

展示活动驱动、待写条数/字节、最近成功时间、连续失败、重试和停机未排空计数；错误脱敏。文件不支持无限历史全盘扫描或全文搜索，大规模查询可选择 PostgreSQL。本次不宣称多实例共享 SQLite 或分布式账务。

## 10. 界面设计

### 10.1 用户端

- 独立布局和样式命名空间，复刻 pro-api 的侧栏、顶部、卡片、列表、弹窗交互，不污染桌面管理端样式。
- 首页：问候、可用余额/冻结或欠费提示、今日/月度用量、最近请求、Codex/Claude 快速接入。
- 用量：真实聚合图表、时间/Key/模型过滤、请求记录、token 与费用；日志与聚合异步延迟要明确提示。
- Key：选分组、创建、单次明文展示、复制、命名、限额、有效期、停用、轮换、删除。
- 充值：人民币金额、汇率、预计美元、备注、状态、取消、详情；订单显示自己的汇率快照。
- 兑换：输入、到账/失败原因、自己的历史，重复点击不重复入账。
- 个人信息：GitHub 名称、头像、状态、退出；不增加密码重置或伪造邮箱注册入口。
- 未登录不读个人 API；401 引导重新登录，封禁、注册关闭和年龄不符分别提示。
- 支持移动宽度、键盘操作、表单标签、焦点、加载/空/失败状态及中英文文案；不以假数据冒充真实用量。

### 10.2 管理端

- 设置新增始终可见的“SaaS 插件”页：启用、站点信息、注册、GitHub OAuth、汇率、请求限制、日志队列/存储。
- 开启后在左侧“系统”第一项显示“SaaS”，进入管理界面；关闭后移除此项。
- 管理界面含总览、用户、分组/定价、充值审核、兑换码、账务/待核对、请求记录和配置入口。
- 用户可查询、封禁/恢复、查看余额流水；金额动作必须使用审计账务服务。
- 分组先选端点，再选默认/自定义批次，再选模型、三类价格和倍率；显示可用账号数和空池警告。
- 审核显示人民币金额、汇率快照、到账美元、用户，避免盲批。
- 批量兑换码一次性展示/导出明文，之后只显示状态和脱敏标识。
- 桌面/Web 读写同一状态，不能用 localStorage 模拟插件开关。

## 11. 故障与兼容性

- GitHub 不可达：登录失败可重试，不因一次网络错误批量退出已有有效会话。
- SQLite 预占失败不转发；结算失败保留恢复状态并告警，不返回虚构成功记录。
- 日志不可写：背压、告警、限制新请求，不回滚已提交真实账务。
- 回调/审核/兑换重放：唯一约束保证不重复发生。
- 用户、Key、分组停用：拒绝新请求，已接收请求仍完成可追溯结算。
- 改价：新请求用新价，旧请求用快照。
- 深链接刷新返回正确应用壳；API 错误和缺失资源不用 SPA fallback 掩盖。
- 关闭 SaaS 后，桌面、Web 主 token、移动配对、账号池、原代理配置及非 SaaS 统计保持可用。
- 备份包括业务表和秘密引用；日志目录/外部数据库有独立备份说明，不能声称 SQLite 备份含全部请求日志。

## 12. 验证与验收

### 12.1 入口与身份

- Rust：开启/关闭根路径、临时重定向、no-store、管理路径刷新、资源/API 404、配置脱敏。
- 前端：桌面不进用户站点、Web 模式分流、插件设置、系统第一项菜单、两类鉴权不串用。
- 本地 mock GitHub：365 天边界、未来/缺失时间、注册关闭的老用户、state 失效/重放/跨浏览器、PKCE、封禁、注销。
- 越权：用户 A 不能读取或修改 B 的 Key、订单、流水、日志；session/Key/移动 token 均不能管理 SaaS。
- 开发代理：用户/公开调用不注入主 token，管理调用保持原行为。

### 12.2 分组与账务

- 默认/多批次、改名/删除、空集合、跨平台、禁用/归档、重试不越组。
- 模型白名单、别名/前缀绕过、缺失价格、零价、缓存读写归类、定点精度与溢出。
- 本地 mock 上游验证 Responses、Chat Completions、Messages 的普通/SSE、重试、断连、缺失 usage 和限额。
- 并发预占、重复结算、超预占欠费限制、失败释放、重启未决请求、人工核对幂等。
- 充值审核/取消竞态、改汇率不变订单、兑换并发、过期/停用、重复请求。
- 断言 SaaS 不增加宿主 `usage_events` 或 SQLite 请求日志，同时保留正确账务与小时聚合。

### 12.3 日志与故障

- 内存容量/字节、背压、重试、正常排空、强制结束的已确认丢失窗口。
- 文件滚动、跨时区过滤、路径限制、坏行、重放去重、归属、清理和秘密扫描。
- Redis 真实集成验证重连、未确认恢复、确认时机、实例隔离和重复投递。
- PostgreSQL 真实集成验证 schema、批次提交、唯一 ID、按用户分页、清理和连接失败。
- 只有 mock 或编译通过不能报告真实连接验证完成；报告明确未具备环境的项目。
- 默认内存＋文件在没有 Redis/PostgreSQL 服务时完整运行。

### 12.4 项目回归与构建

先跑新增定向 Vitest/Rust 测试，再运行 `pnpm typecheck`、`pnpm test:run`、前端构建、Rust 检查/测试、独立服务器 feature 检查和格式检查。修改发布脚本或 sidecar 才追加其专属检查，不修无关失败。

AI Cargo 验证统一复用 `src-tauri/target-codex/`：在 `src-tauri` 运行设置 `CARGO_TARGET_DIR=target-codex`，在仓库根运行设置指向同一目录的绝对路径。不得创建第三个 target，不使用 dev 专用 `src-tauri/target/`。

完成标准：所列完整用户链路通过真实 API 运行，提供权限、金额、流式完成和日志驱动的验证证据。只有页面、配置占位、不能扣费的 Key 或未接线的驱动枚举不算完成。

## 13. 本次不包含

- 在线支付、自动收款回调、退款通道。
- Vue 运行时迁入、pro-api 后端整体复制。
- 邮箱密码、组织/多租户管理员、套餐订阅、分销。
- 动态第三方插件、插件市场、任意脚本。
- 全业务迁 PostgreSQL、多实例共享 SQLite、分布式余额账务。
- 默认内存日志零丢失、无限历史全文扫描、自动跨驱动迁移历史。

这些边界不减少人工充值、兑换码、GitHub 登录、用户面板、分组计费、Redis 队列、PostgreSQL 日志驱动的完整交付要求。
