# 每小时自动检查更新设计

日期：2026-08-11

状态：已确认设计，待编写实现计划

## 目标

将桌面端自动更新检查从“每天最多检查一次”调整为：

- 应用启动后立即检查一次。
- 应用运行期间每隔一小时检查一次。
- 检查失败时保持静默，不打断用户当前操作。

## 范围

本次只调整全局自动更新提示组件及其测试：

- 修改 `src/components/updates/AutoUpdatePrompt.tsx`。
- 修改 `tests/AutoUpdatePrompt.test.tsx`。
- 不修改 Tauri updater 配置、更新清单格式或后端代码。
- 不改变“更新”页面的手动检查行为。

## 现状

`AutoUpdatePrompt` 已在 `src/App.tsx` 中全局挂载，并在桌面环境启动时调用 Tauri updater 的 `check()`。当前实现使用 `localStorage` 保存本地日期键，同一自然日内只执行一次自动检查。

## 方案

采用组件内定时检查方案：

1. 保留桌面环境判断。
2. 组件挂载后立即执行一次更新检查。
3. 创建间隔为 `60 * 60 * 1000` 毫秒的 `setInterval`。
4. 每次定时触发时，如果已有检查请求进行中，则跳过本轮。
5. 组件卸载时清理定时器，并使未完成请求的结果失效。
6. 删除按日期限流的 `localStorage` 读写和日期键辅助函数。

该方案复用现有 updater API 和弹窗状态，不引入新的全局服务或 Rust 定时任务，改动范围最小且符合当前应用生命周期。

## 行为与数据流

### 自动检查

- 非桌面环境：不调用 `check()`，不创建定时器。
- 桌面环境挂载：立即调用一次 `check()`。
- 后续每小时：调用一次 `check()`，但不会与尚未完成的检查并发。
- 返回更新对象：写入组件状态并显示更新弹窗。
- 返回空结果：不显示弹窗。
- 抛出错误：忽略错误，保持自动检查静默。

### 弹窗重复提示

用户点击“稍后”后，弹窗状态会被清空。下一小时如果仍检测到同一版本，组件会再次显示该版本提示。此行为只改变检查频率，不增加新的“忽略此版本”持久化策略。

### 手动检查

`src/screens/UpdatesScreen.tsx` 的手动检查流程保持现状，不与自动检查共享状态或限流记录。

## 生命周期与并发

自动检查函数需要通过组件生命周期管理以下状态：

- 定时器句柄：用于卸载时调用 `clearInterval`。
- 请求进行中标记：防止网络请求耗时超过一小时或定时器重复触发时产生并发检查。
- 取消标记：组件卸载后，已完成的异步请求不得更新已卸载组件状态。

检查失败后应释放进行中标记，使下一轮仍可继续检查。

## 测试设计

更新 `tests/AutoUpdatePrompt.test.tsx`：

1. 验证组件挂载后立即调用一次 `check()`，并在返回更新时显示弹窗。
2. 使用 Vitest 假定时器验证未满一小时不会再次调用，满一小时后再次调用。
3. 验证关闭弹窗后，下一小时检测到同一版本时会再次显示。
4. 验证组件卸载后推进时间不会触发新的检查。
5. 验证检查失败不会渲染错误提示，并且后续定时检查仍可执行。

原有更新下载、安装和重启行为不在本次改动范围内。

## 验收标准

- 桌面应用启动后能立即自动检查更新。
- 应用持续运行时每小时最多发起一次自动检查。
- 检查请求不会重叠。
- 用户关闭更新提示后，同一版本可在下一小时再次提示。
- 非桌面环境不触发自动检查。
- 组件卸载后不会留下定时器或异步状态更新。
- 相关测试和 `pnpm typecheck` 通过。

## 非目标

- 不实现后台进程或应用未运行时的更新检查。
- 不修改更新源、签名校验或安装流程。
- 不改造手动更新页面。
- 不新增用户可配置的检查间隔。
