# 算力池账号优先级、并发限制与暂停状态设计

## 目标

为算力池账号增加可配置的路由优先级和并发上限，支持批量暂停/恢复账号，并在账号列表中实时显示正在处理请求的账号及其并发占用情况。

## 背景与现状

当前算力池从启用成员中按池内排序轮询，路由选择会排除归档账号、非 `ok` 状态账号以及处于重试/冷却窗口的账号，但没有账号优先级和并发限制。

当前账号状态为 `ok`、`warning`、`error`、`revoked`。账号可以保留在算力池成员关系中，即使当前状态不可路由；这项行为需要继续保留，并新增 `paused` 状态。

当前桌面端使用 Tauri command，独立服务端使用 Web command/事件桥。路由代理由 `RouteProxyRuntimeState` 管理生命周期，适合在同一运行时中保存账号活动租约。

## 设计决策

### 1. 配置持久化

在 `route_credentials` 增加两个配置字段：

- `route_priority INTEGER NOT NULL DEFAULT 3`：取值范围 `1-5`，数字越小优先级越高。
- `max_concurrency INTEGER NOT NULL DEFAULT 1`：取值必须大于等于 `1`，表示账号允许同时处理的上游请求数。

默认优先级使用 `3`，使历史账号升级后仍保持同一优先级下的现有轮询行为；默认并发数使用 `1`，兼容只允许单会话的上游站点。

新增账号、官方账号导入、API 账号创建和账号复制都使用上述默认值。账号编辑时校验优先级为 `1-5`，并发数为不小于 `1` 的整数。

### 2. 暂停状态

新增账号状态 `paused`，中文显示为“暂停”。

- 暂停账号仍保留在算力池成员列表中。
- 任何自动路由选择都跳过暂停账号。
- 暂停账号不参与 `/models` 聚合和自动模型测试选账号。
- 手动指定账号进行模型测试时仍允许打开该账号，但请求开始前必须拒绝暂停、归档或其他不可路由状态，并返回可识别的校验错误。
- 将账号恢复为 `ok` 后，无需重新加入算力池即可参与下一次路由。

### 3. 路由选择算法

账号选择在现有模型映射过滤之后执行，顺序如下：

1. 读取当前平台的算力池成员，并过滤归档账号、暂停账号、非 `ok` 状态账号以及仍处于 `next_retry_at`/`cooldown_until` 窗口的账号。
2. 根据请求模型执行现有模型能力过滤。
3. 找出剩余账号中的最小 `route_priority`。
4. 只在该优先级内查找尚未达到 `max_concurrency` 的账号。
5. 同一优先级的可用账号继续使用现有游标轮询。
6. 如果该优先级没有可获得并发租约的账号，则继续查找更大的优先级。
7. 如果所有优先级都没有可用账号，返回现有路由失败结构，并将失败原因区分为无可用账号、模型不匹配或并发已满。

优先级只影响不同等级之间的选择，不替代同等级内的轮询。请求重试时，失败账号先释放租约，再从当前候选集合中继续选择，避免失败账号占用并发额度阻塞后续账号。

### 4. 进程内并发租约

并发限制使用运行时内存状态，不把活动请求数写入 SQLite：

- `RouteCredentialActivityRegistry` 按账号 ID 保存当前活动数。
- `try_acquire(id, max_concurrency)` 在互斥锁保护下检查并递增活动数，成功后返回带 `Drop` 释放逻辑的租约。
- 活动数达到上限时返回未获取结果，路由器继续尝试同优先级其他账号或下一级账号。
- 上游响应、传输错误、响应读取错误、协议转换失败和请求取消都会经过同一释放路径。
- 进程退出时内存状态自然清零，不会产生数据库脏锁。

该限制的作用域是当前 AI Switch 进程。它覆盖桌面应用内置代理和独立服务端各自的运行时，不承诺跨多个独立 AI Switch 进程共享并发额度。

### 5. 活动状态同步

每次租约成功获取或释放时，向当前运行时的事件出口发送 `route-credential-activity` 事件，事件载荷为：

```json
{
  "platform": "codex",
  "credential_id": "credential-id",
  "active_request_count": 1,
  "max_concurrency": 2
}
```

桌面端通过 Tauri event listener 接收事件；Web 端通过现有 WebEventBroadcaster/WebSocket 事件桥接收事件。账号列表首次加载时由服务端将当前 `active_request_count` 和 `max_concurrency` 一并返回，避免监听建立前出现空状态。

前端只在 `active_request_count > 0` 时显示动效。账号名称右侧显示绿色脉冲点和 `当前数/上限`，例如 `1/2`；活动数为零时隐藏该标记。动效同时提供屏幕阅读器文本“正在处理请求，当前 1/2”。

### 6. 账号管理界面

账号编辑面板增加：

- “路由优先级”下拉框，选项 `1` 至 `5`，旁边显示“数字越小优先级越高”。
- “最大并发数”数字输入框，最小值 `1`，默认值 `1`。
- 状态下拉框新增“暂停 (paused)”。

账号列表在名称区域显示优先级和并发配置的紧凑标签，避免用户必须打开编辑面板才能确认算力池路由配置。

选中账号后的批量操作区域增加“批量设置状态”下拉框和确认按钮，支持设置为：

- 正常
- 暂停
- 警告
- 异常
- revoked

批量状态更新在一个数据库事务中执行：去重账号 ID、校验账号全部存在、校验目标状态合法，任一账号失败则整体回滚。批量操作完成后清空选择并刷新账号列表、算力池状态和模型列表缓存。

### 7. 数据接口

Rust 和 TypeScript 的 `RouteCredential` 增加：

- `route_priority`
- `max_concurrency`
- `active_request_count`

其中前两个字段来自数据库，`active_request_count` 来自运行时活动注册表，数据库查询模型使用默认值兼容旧字段映射。

新增批量状态 command：

```text
set_route_credential_statuses(ids: string[], status: AccountStatus) -> void
```

新增活动事件监听所需的前端 transport 封装，但不新增独立轮询接口；列表 command 负责初始活动数，事件负责增量更新。

## 错误处理与边界

- 优先级不是 `1-5` 时返回 `validation.route_credential_priority`。
- 并发数不是整数或小于 `1` 时返回 `validation.route_credential_concurrency`。
- 批量状态更新传入空 ID 列表时返回 `validation.route_credential_selection_empty`。
- 批量状态更新遇到不存在账号或非法状态时整体回滚。
- 所有候选账号并发已满时返回明确的 `route_pool.concurrency_exhausted`，不将账号标记为异常或冷却。
- 账号因上游错误进入冷却后，活动租约仍会先释放，再由现有失败记录链路保存冷却状态。
- 手动暂停账号后，已在途请求不被取消；请求完成后活动数归零，后续请求跳过该账号。
- 修改账号最大并发数不会强制中断已有请求。新上限小于当前活动数时，账号暂时不可再接收新请求，直到活动数降到上限以下。
- `/models` 只聚合当前可路由账号的模型映射；账号暂停或状态不可用时不贡献模型。

## 测试策略

### Rust

- 迁移测试确认历史数据库可加载，旧账号默认优先级为 `3`、并发数为 `1`。
- Repository 测试覆盖创建、读取、编辑、复制和批量状态事务。
- 选择器测试覆盖：
  - 优先级 `1` 有可用账号时不选择 `2`。
  - 优先级 `1` 全部冷却、异常、暂停或并发已满时选择 `2`。
  - 同优先级继续轮询。
  - 模型映射过滤发生在优先级选择之前。
  - 所有优先级都并发已满时返回 `route_pool.concurrency_exhausted`。
- 并发注册表测试覆盖达到上限、释放后重新获取、不同账号互不影响以及租约 `Drop` 释放。
- 代理集成测试确认请求期间活动事件包含账号 ID、当前活动数和上限，响应完成后发送归零事件。

### 前端

- 账号编辑测试确认优先级、并发数和暂停状态写入 `update_route_credential`。
- 批量状态测试确认复选框选中多个账号后调用一次批量 command，并在成功后清空选择和刷新缓存。
- 活动事件测试确认账号名称右侧显示 `1/2` 和脉冲标记，归零事件后隐藏。
- 现有账号列表、算力池成员、模型映射和归档测试继续通过。

## 不采用的方案

不使用数据库实时计数作为并发锁，也不使用仅前端计数。前者在进程崩溃、强制退出和多次重试时容易产生脏状态，后者无法提供服务端并发保证。
