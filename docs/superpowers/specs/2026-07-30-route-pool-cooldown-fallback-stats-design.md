# 算力池全冷却回退与账号请求统计设计

## 背景

算力池目前会过滤所有尚未到重试时间的账号。当所有账号都处于冷却期时，代理直接返回空池错误，无法继续服务。账号列表也缺少按账号聚合的成功、失败和成功率信息，难以判断账号质量。

## 目标

- 当所有账号都在冷却时，立即半开放探测最早可重试的账号，不返回空池。
- 单次请求中每个账号最多尝试一次，避免同一个异常账号循环占用请求。
- 在账号列表展示请求总数、成功数、失败数和成功率。
- 移除账号行中邮箱与平台/智能体占位文本，保留账号名称、类型、池状态、额度和重试状态。

## 方案

### 全冷却回退

选池查询分两步：

1. 查询启用、状态允许路由的全部池成员，同时读取 `next_retry_at` 和 `cooldown_until`。
2. 先保留当前已可重试的账号；如果结果为空，则按最早可重试时间升序选择一个账号立即探测。缺失或无法解析的时间视为可重试，时间相同按原池排序保持稳定。

代理和模型测试共享同一个 `select_pool_credentials` 辅助函数。半开放探测失败仍按现有失败计数和冷却策略递增；成功立即清除临时失败字段。

### 账号统计

复用现有 `usage_events` 中 `source_label = 'route_proxy'` 和 `route_pool_model_test` 的请求事件：

- `success = true` 计入成功数。
- `success = false` 计入失败数。
- 总数为成功数与失败数之和。
- 成功率为 `success / total * 100`；总数为 0 时返回 `null`，避免显示虚假的 100%。

新增按平台聚合的账号统计查询，并在 `list_route_credentials` 返回的账号对象中附带 `request_count`、`success_count`、`failure_count`、`success_rate`。没有事件的账号返回 0、0、0、`null`。

统计查询使用单次聚合 SQL，避免每个账号单独查询。统计范围不受请求列表分页影响，继续覆盖历史事件。

### 前端展示

账号名称下方显示一行紧凑统计：`请求 N · 成功 N · 失败 N · 成功率 N%`。无请求时显示 `暂无请求`。邮箱和 `credential.platform` 占位文本不再显示；账号类型和池状态标签保留。

## 错误处理

- 全冷却回退只改变候选选择，不修改账号冷却时间。
- 如果池成员为空，仍返回现有 `route_pool.empty`。
- 聚合统计查询失败不影响账号路由，列表命令返回数据库错误并由前端显示加载失败。
- 统计只读取 usage event，不记录新的统计事件，避免重复计数。

## 测试

- 全部账号冷却时立即选择最早到期账号；时间相同按池顺序稳定选择。
- 有可用账号时不选择仍在冷却的账号。
- 账号统计正确计算成功、失败、总数和成功率；无事件返回空成功率。
- 代理与模型测试事件都计入对应账号统计。
- 前端账号行显示统计并不再显示邮箱/平台占位文本。
