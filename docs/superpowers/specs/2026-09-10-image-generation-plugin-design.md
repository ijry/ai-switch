# 生图插件、算力池与 SaaS 设计

日期：2026-09-10

> **实施范围说明：** 本次交付实现 Codex/Gemini 普通分组的文生图、会话与资产管理，以及 SaaS `/v1/images/generations` 按张计费。`/v1/images/edits` 仅完成路径与 `image.edit` 能力识别，编辑请求的协议转换、multipart 处理和插件 UI 留到下一阶段；SaaS 本阶段采用“每张固定售价 + 分组倍率”，暂不做尺寸/质量差异定价。

状态：第一阶段已实施。

## 1. 目标与原则

在现有 AI Switch 架构中增加生图插件，使桌面/Web 用户可以管理生图会话，并让 SaaS 用户通过兼容接口调用生图模型。功能必须复用现有“平台 → 动态分组 → API 成员/官方凭证 → 模型映射 → 路由代理”结构，不引入新的生图平台、供应商字段、特殊成员类型或跨平台资源池。

已确认原则：

- 生图插件与 SaaS 一样集中在独立目录，便于以后插件化，但第一阶段仍随主程序编译和发布。
- 生图组就是普通动态分组，不增加组类型；用户可在 Codex、Gemini 等既有智能体页面创建并激活普通分组。
- 分组成员仍只有两种：API 成员和官方凭证。
- API 成员通过现有 `interface_format` 选择上游接口格式；`base_url` 决定请求官方 API 还是 sub2api、New API 等兼容中转站。
- 官方凭证不让用户选择接口格式，由平台内置适配器决定调用方式，并且只在其所属智能体平台内使用。
- 分组、成员和凭据继续要求平台一致，不做 Codex 与 Gemini 凭据混组或跨平台故障切换。
- 生图插件默认从所选平台的当前激活分组读取生图模型；SaaS Key 仍固定绑定普通非内部分组，是否激活不影响 SaaS。

## 2. 用户体验

### 2.1 生图插件

新增独立生图页面，提供：

- 平台选择：第一阶段支持 Codex 和 Gemini。
- 当前激活分组及可用生图模型展示。
- 会话创建、改名、归档、删除和历史查看。
- 文生图；接口和上游支持时提供图片编辑。
- 提示词、模型、尺寸、质量、数量、背景等参数。
- 任务状态、失败原因、实际使用成员、耗时和成本展示。
- 生成结果保存、下载和在会话内继续编辑。

插件不自行选择任意分组。切换平台后，它读取该平台的当前激活组，并只展示组内声明生图能力且当前可调度的模型。激活组没有生图模型时，明确提示用户前往该智能体页面激活或配置包含生图模型的组，不回退其他组。

### 2.2 分组与成员

例如 Codex 页面可以创建普通的“生图组”，成员仍为：

1. API 成员：OpenAI 官方 API Key、sub2api Key、New API Key 或其他兼容中转；用户配置 `base_url`、`api_key`、`interface_format` 和模型映射。
2. 官方凭证：现有 Codex 官方账号；核心按 Codex 官方协议调用，不暴露接口格式选择。

Gemini 页面同理，可在普通组中加入 Gemini API 成员和 Gemini 官方凭证。Codex 组不使用 Gemini 凭据，Gemini 组不使用 Codex 凭据。

## 3. 上游接口格式

不增加 `provider`。协议转换完全由成员类型、平台和 `interface_format` 决定。

| 平台 | 成员类型 | 接口格式 | 生图方式 |
| --- | --- | --- | --- |
| Codex | API | `openai` | `POST /v1/images/generations`、`POST /v1/images/edits` |
| Codex | API | `openai-responses` | Responses API 的 `image_generation` 工具 |
| Codex | 官方凭证 | 内置 | 官方 Responses 与 `image_generation` 工具 |
| Gemini | API | `gemini` | Gemini `generateContent` 图片内容部件 |
| Gemini | 官方凭证 | 内置 | Gemini 官方原生生图流程 |

同一种接口格式同时适用于官方 API 与中转站。例如 sub2api 或 New API 兼容 OpenAI Images 时，使用 `interface_format=openai`，只需配置其 `base_url` 和 Key；没有品牌专用转发代码。只有上游协议真实不兼容现有格式时，才新增接口格式适配器。

## 4. 模型能力

现有模型映射增加可选能力字段：

```json
{
  "from": "gpt-image",
  "to": "gpt-image-2.5-sunburst",
  "capabilities": ["image.generate", "image.edit"]
}
```

Gemini 示例：

```json
{
  "from": "nano-banana",
  "to": "gemini-3.1-flash-image",
  "capabilities": ["image.generate", "image.edit"]
}
```

兼容规则：

- 旧映射没有 `capabilities` 时保持现有文本路由行为，不自动视为生图模型。
- API 成员的能力由用户配置、模型拉取结果或连接测试确认。
- 官方凭证能力由平台内置模型目录与运行时探测提供。
- 生图调度先按操作能力和模型过滤，再复用现有优先级、并发上限、模型暂停、冷却、重试和账号切换。
- 请求中的尺寸、质量、透明背景、输入图片等参数必须通过能力检查；不得在跨成员重试时静默丢弃不支持的参数。

## 5. 核心调用链

### 5.1 插件调用

```text
平台
→ 当前激活普通分组
→ API 成员与官方凭证
→ 生图能力及模型过滤
→ 现有优先级/并发/冷却调度
→ 按成员接口格式或官方适配器转换
→ 上游请求
→ 统一图片结果
→ 资产落盘、会话记录和用量记录
```

### 5.2 统一内部请求

插件和 SaaS 共同使用内部领域模型：

```text
ImageRequest
- operation: generate | edit
- prompt
- input_images
- model
- size / aspect_ratio
- quality
- count
- background
```

统一响应保存：成功图片、MIME 类型、修改后的提示词、上游响应 ID、成员 ID、上游模型、实际数量、费用及原始元数据。适配器负责在内部结构与 OpenAI Images、OpenAI Responses、Gemini 原生格式之间转换。

## 6. 会话与资产

后端建议集中在 `src-tauri/src/imagegen/`，前端集中在 `src/imagegen/`。数据包含：

- `imagegen_sessions`：标题、平台、创建时间、更新时间和归档状态。
- `imagegen_messages`：用户提示、请求参数、状态、模型、实际成员、上游响应 ID、错误和费用。
- `imagegen_assets`：消息、文件路径、MIME、哈希、尺寸和字节数。

生成图片写入应用数据目录的 `imagegen/{session_id}/{message_id}/`。数据库不保存大块 base64；上游返回 URL 时，服务端受大小和类型限制地下载后落盘。资产读取通过鉴权接口提供，防止把本机路径暴露到 Web 页面。

## 7. SaaS 配置与调用

SaaS 继续使用普通核心分组：

- API Key 固定绑定一个非内部、未删除的普通组。
- Codex 组可配置并出售其组内可用的 Codex 生图模型。
- Gemini 组可配置并出售其组内可用的 Gemini 生图模型。
- SaaS 请求候选来自 Key 绑定组本身，不要求该组是普通路由激活组。
- SaaS 管理只配置公开模型、映射、价格和限制，不创建或修改核心分组及成员。

下游统一支持 OpenAI Images 兼容入口：

```text
POST /v1/images/generations
POST /v1/images/edits
```

SaaS Key 绑定 Codex 组时使用 Codex 组适配路径；绑定 Gemini 组时，内部把同一公开请求转换成 Gemini 原生协议。`GET /v1/models` 只返回绑定组中已配置、具有相应能力且至少有一个可用成员的公开模型。

SaaS 模型配置需要在现有 token 价格之外增加图片定价：

- 公开模型名和上游模型名。
- 允许操作：生成、编辑。
- 1K、2K、4K 或明确尺寸的单张价格。
- 质量与操作倍率。
- 单次最大张数、输入图片数量、请求体大小、超时和并发限制。

## 8. 图片计费

参考 sub2api 和 New API，图片默认按实际成功张数计费，不套用文本 token 价格：

```text
预占金额 = 请求张数 × 请求参数对应的最高确定售价 × 分组倍率
实际金额 = 成功图片数量 × 实际尺寸/质量售价 × 分组倍率
```

- 请求前冻结预占金额和 Key 限额。
- 全部失败且确认未产出图片时全额释放。
- 部分成功只扣成功图片。
- 实际金额低于预占金额时释放差额。
- 无法确认是否产生费用时进入 `pending_review`，不能直接重复扣费或退款。
- 整个下游请求使用一个幂等 `request_id`；上游重试和成员切换不产生多次下游扣款。
- 本地插件只记录成本，不扣钱包；SaaS 才执行余额或订阅结算。

用量记录至少包含请求数、请求张数、成功张数、模型、上游模型、尺寸、质量、操作、成员 ID、会话 ID、上游响应 ID、下游扣费和可获得的上游成本。

## 9. 错误与安全

- API Key、官方 token 和中转站 Key继续只从现有密钥存储读取，不写入会话、日志或图片元数据。
- 图片输入、输出和 multipart 请求分别设置体积、张数、像素及超时上限。
- 上游 URL 下载禁止访问本机、内网和元数据地址，并限制重定向、MIME 和最大字节数。
- Web/SaaS 资产下载校验用户、Key 或会话所有权。
- 明确区分不支持的模型、参数、余额不足、无可用成员、上游拒绝和内容安全错误。
- 只有可重试的传输、限流和暂时性上游错误触发成员切换；确定性的参数或内容错误不遍历全组。

## 10. 测试与验收

1. Codex/Gemini 普通组仍只接受同平台的 API 成员和官方凭证，成员结构及原有文本代理无回归。
2. OpenAI 官方 API、OpenAI 兼容中转、OpenAI Responses、Codex 官方凭证、Gemini API 和 Gemini 官方凭证分别完成协议转换测试。
3. 生图插件只显示所选平台激活组内的图片模型；空组、非激活组和其他平台凭据不被误用。
4. 模型、参数、暂停、冷却、并发和重试过滤正确；确定性失败不切换账号。
5. 会话 CRUD、图片落盘、资产鉴权、重启恢复和删除清理正确。
6. SaaS Key 只能访问绑定组的公开图片模型，非激活公开组仍可供 SaaS 使用，内部组立即拒绝新请求。
7. 预占、成功结算、部分成功、失败退款、超时待审和幂等重放账务正确。
8. 文本端点、文本计价、`/v1/models` 和现有 SaaS 日志保持兼容。

## 11. 分阶段交付

1. 核心能力：模型能力字段、图片领域请求、OpenAI Images 与 Gemini 适配、激活组调度和用量记录。
2. 插件体验：会话、任务、资产存储、结果查看和下载。
3. SaaS：图片模型管理、兼容端点、按张预占/结算、聚合统计和日志。
4. 完善：图片编辑、官方凭证覆盖、更多接口格式、能力探测和异步批量任务。

第一阶段不实现动态插件加载、跨平台分组、跨平台故障切换、供应商品牌字段或独立生图平台。
