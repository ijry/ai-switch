# 算力池账号临时失败重试与冷却设计

## 背景

当前算力池代理在网络错误、上游连接失败以及部分可重试 HTTP 状态出现时，直接把账号状态更新为 `error`。池查询只选择 `status = 'ok'`，因此一次临时网络抖动可能让账号永久退出池，必须人工编辑状态才能恢复。

## 目标

- 临时性错误按账号、错误类型累计，并计算下一次允许尝试的时间。
- 连续 3 次临时失败后进入冷却期，而不是标记为永久不可用。
- 冷却结束后自动进行半开放探测；成功后清除失败状态并恢复正常轮询。
- 明确的永久认证失效仍保持 `revoked`，不自动重试。
- 状态在 SQLite 中持久化，程序重启和多请求并发下行为一致。

## 方案

在 `route_credentials` 增加以下字段：

- `transient_failure_count INTEGER NOT NULL DEFAULT 0`
- `next_retry_at TEXT`
- `cooldown_until TEXT`
- `last_failure_kind TEXT`
- `last_failure_message TEXT`

`status` 继续表示账号生命周期状态：`ok`、`revoked` 等。临时失败不改变 `status`；`revoked` 只用于确认凭证永久失效。

### 临时错误分类

- 网络连接失败、DNS/连接超时、上游 `502/503/504`：`transient`。
- 上游 `401/403`：只有在错误内容明确表示凭证失效时才按永久错误处理；否则按临时认证失败处理。
- `invalid_grant`、refresh token revoked、明确无权限：`permanent`，立即设置 `status = 'revoked'`。
- 请求成功：清除临时失败字段。

### 退避策略

按连续失败次数计算下一次时间：

| 失败次数 | 基础延迟 |
| --- | --- |
| 1 | 30 秒 |
| 2 | 2 分钟 |
| 3 及以上 | 冷却 10 分钟 |

延迟增加 0.8 到 1.2 的随机抖动，避免多个请求同时唤醒。达到第 3 次时设置 `cooldown_until`；冷却结束后允许一次半开放探测。探测成功立即清零；失败则重新按冷却策略计算时间。

### 选池与请求流程

1. 查询启用且 `status = 'ok'` 的池成员。
2. 过滤 `next_retry_at > now` 或 `cooldown_until > now` 的账号；时间已到的账号可参与选择。
3. 单次入站请求中，每个账号最多尝试一次，失败后切换到下一个账号。
4. 临时失败通过原子更新递增计数并写入下一次时间；永久失败更新为 `revoked`。
5. 任一上游请求成功后原子清除临时失败字段。

原子更新必须在仓储层完成，避免并发请求读取相同计数后互相覆盖。更新条件应包含账号 ID，并由数据库返回更新后的计数和时间，供日志使用。

## 错误处理与兼容性

- 现有 `error` 状态记录保留，历史账号不会被自动改写；新的代理路径不再因临时错误写入 `error`。
- 已处于 `error` 且仍在池中的账号可通过一次成功请求恢复为 `ok`，但是否纳入候选由迁移后的恢复规则决定。
- 失败信息截断后写入 `last_failure_message`，避免把完整上游响应或密钥写入数据库。
- 池完全没有可尝试账号时，继续返回 `route_pool.empty` 或“所有账号暂时冷却”的可区分错误信息。

## 测试

- 仓储测试：失败计数原子递增、退避时间、冷却到期、成功清零、永久失败状态。
- 代理测试：网络错误不会写入 `error`；连续三次进入冷却；冷却账号被跳过；成功探测恢复；永久认证错误变为 `revoked`。
- 并发测试：两个失败请求不会丢失一次计数。
