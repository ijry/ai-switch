# 智能体共享动态分组与 SaaS 扩展设计

状态：核心交互已在对话确认；书面修订待审阅。本文不表示代码已实现或验证完成。

本文件修订 `2026-09-07-saas-plugin-design.md` 的分组架构，不改变其余 SaaS 完整交付范围。当前代码在专用 `task/164` 工作树中保留，旧 SaaS 独立分组实现已暂停。

## 1. 已确认规则

- 用户要求不再由 SaaS 创造第二套分组，智能体分组成为唯一来源。
- 原“算力池、未入池、已归档”全部变为普通动态分组；算力池改名“默认组”。后两项也可以重命名、编辑和激活。
- 底栏统计入口右侧增加“+”创建组；右击已有组编辑。统计仍是统计视图，不是分组。
- 普通算力池采用单组激活：各智能体分别维护自己的激活组。
- SaaS 模式所有非内部分组都可用，不受普通算力池激活组限制；一个 Key 固定绑定一个组。
- 倍率、模型映射、价格等继续实施，存储在 SaaS 扩展表。SaaS 管理页不再创建或删除组。

## 2. 方案选择与模块边界

采用“核心分组作为唯一数据源 + SaaS 一对一扩展”，而不是在 SaaS 中复制核心组再同步。复制方案会产生名称、成员和删除状态不同步的问题，违背本次调整目标。

不采用“把多个激活组合并成一个候选池”。用户明确选择单组激活；只有 SaaS Key 可以独立访问其他非内部组。

核心负责分组生命周期、成员归属、普通路由激活和内部标记，即使 SaaS 关闭也完整工作。SaaS 仅消费核心稳定 ID 与受限成员查询接口，维护用户授权、模型计费和财务记录。

## 3. 核心数据和迁移

### 3.1 持久化约束

- 核心分组记录稳定 ID、智能体平台、名称、排序、内部标记、创建/更新时间、软删除状态。
- 核心成员关系保证一个账号只属于一个同平台分组；移动不是复制，不得让同一账号隐式落入多个组。
- 每个平台最多且正常状态下始终有一个激活组；切换在事务内完成，不出现短暂空激活或双激活状态。
- 核心组与成员数据由宿主迁移和备份体系管理，不放进 `saas_` 业务表。具体 SQL 与服务接口在实施计划中确定，不保留双写成员真相。

### 3.2 旧数据迁移

每个平台按迁移前的状态一次性分配：

| 原状态 | 新分组 | 初始激活 |
| --- | --- | --- |
| 未归档且原池成员启用 | 默认组 | 是 |
| 未归档且不是启用的原池成员 | 未入池 | 否 |
| 已归档，不论过去是否入池 | 已归档 | 否 |

- 迁移事务覆盖分组、成员和激活状态，重复启动不重复创建或移动账号。
- 三个名字只是初始名称，不作为授权键，也不是保留名称。之后改名不会改变成员、Key、价格或账务关联。
- 历史 `archived_at` 不因迁移、改名、激活或切换分组而清空；恢复归档账号仍须显式操作。
- 新建组及迁移组默认非内部；SaaS 仍默认关闭，组在显式完成模型和价格配置前不接受 SaaS 推理请求。管理员可在智能体分组编辑中标记内部；是否允许请求还必须通过用户、Key 与余额校验。
- 对迁移出的“已归档”组同样保留账号级安全限制，不能因为该组可激活便自动恢复历史账号。

### 3.3 创建、编辑、移动和删除

- 创建组选择当前智能体，输入名称并设置是否内部；创建本身不抢占当前激活组。
- 编辑名称、内部标记和排序不改变账号归属；激活是一项明确操作，与选中查看区分。
- 账号批量操作使用“移动到分组”；现有批量名筛选保留，可用来一次选中并移动一批账号。
- 用户界面中创建/导入账号以当前查看组作为明确目标；无界面的旧入口使用所属平台激活组，不能产生不可见的无组账号。
- 删除仅允许空的非激活组，并采用软删除。非空组提示先移动账号，激活组提示先切换，不能级联删除 Key、日志或账务。
- 归档保持账号级状态操作，不再把组名解释为归档动作；显式恢复账号也不自动移动到其他组。

## 4. 智能体界面

- 底栏显示按排序读取的动态组、统计入口和其右侧的“+”；不再硬编码三个组名作为视图枚举。
- 浏览中的组与正在承接普通路由的组用不同标识显示，防止点击标签就悄悄改变生产流量。
- 组名右键打开编辑菜单；同时提供键盘可达的菜单入口，避免只能使用鼠标右键。
- 编辑界面提供名称、内部标记和激活操作，安全删除遵循空组/非激活规则。
- 账号列表、计数、分页、跨页勾选、批量操作和模型展示都传递稳定组 ID；切组后清空旧组选择，避免误操作。
- 底栏分组较多时可横向滚动，“+”和统计入口保持可达。
- 保留普通算力池的代理入口、用量统计、健康检查和协议适配；“默认组”是组名，不要求把产品中所有“算力池”概念都替换掉。

## 5. 两种路由范围

### 5.1 普通算力池

平台解析 → 当前激活组 → 该组成员 → 现有健康/归档/模型能力检查 → 优先级、并发限制、重试和转发。

空组或无可用账号时明确失败，禁止回退默认组、其他组或全平台账号。客户端请求不能自行指定另一核心组绕过普通入口范围。

### 5.2 SaaS

用户 Key → 固定核心组 ID → 非内部且未删除检查 → 模型映射/价格校验 → 该组成员 → 健康/归档/模型能力检查 → 预占和受限代理 → 结算和日志。

- 候选来源是 Key 绑定组本身，不是“先取普通激活池，再与 Key 组求交集”。后者会错误地阻断非激活组。
- 组未激活不影响 SaaS 可用性；组为内部则不允许 SaaS 使用，即使它是普通路由激活组也不例外。
- 内部标记变更需在服务端新请求授权中检查；仅隐藏用户下拉框不够。已存在的 Key 同样受约束。
- 已接收请求保留授权与价格快照；管理员移动账号、切组或调整公开状态不能造成重复扣费或丢失结算。
- 模型映射只能映射到绑定组可用的模型，不能利用账号前缀、别名或平台请求头访问组外账号。

## 6. SaaS 扩展及管理

| 数据 | 归属 |
| --- | --- |
| 组 ID、名称、平台、成员、排序、激活、内部标记 | 核心智能体 |
| 倍率、请求限制、配置版本 | `saas_group_settings`，按核心组 ID 一对一关联 |
| 公开模型名、上游模型映射、模型选择、输入/缓存/输出价格 | `saas_group_models` |
| Key、预占、账务、聚合和明细引用 | 稳定核心组 ID；历史不随改名重写 |

- 移除旧设计中的 `saas_groups` 和 `saas_group_batches`，不维护第二份名称或成员集合。
- SaaS 管理可查看所有受支持平台的核心组及内部状态；非内部组自动进入可配置集合，不需要复制或新建。
- 管理页仅编辑 SaaS 扩展，名称、端点和成员只读；需要变更时提示前往智能体分组管理。
- 用户侧不显示内部组，不返回其账号、模型或配置。未配置模型/价格的非内部组标记未就绪，不能把未配置当零价、全模型或全账号授权。
- 扩展保存必须要求核心组存在且平台受支持；不允许通过伪造组 ID 顺便创建核心组。
- 财务、Key、用量和日志统一引用核心 ID；软删除或转内部保留历史，但拒绝新的 SaaS 请求。

## 7. 验收重点

1. 从已有账号数据库迁移：三类账号各入正确组，无重复、无丢失、无自动解除归档；重复启动不重置用户分组。
2. 默认组初始激活，改名不改流量；创建、查看另一组不改变激活，显式切换才改变普通请求的上游。
3. 同平台单组激活且跨平台互不干扰；并发激活仍保持约束，空组不回退其他账号。
4. 成员移动、分页和批量选择按组隔离；跨平台移组、伪造组 ID 和越权操作失败。
5. 非激活且非内部组的 SaaS Key 正常使用自己的账号；内部激活组可用于普通路由，但不可用于 SaaS。
6. 组改为内部后旧 Key 新请求立即拒绝；改回公开不需要重建 Key；进行中的结算保持幂等。
7. SaaS 管理没有创建/删除组操作，配置编辑不改核心成员；模型映射不能越组，缺价/空组不自动放行。
8. 改名、软删除不破坏账务和日志关联；非空/激活组删除被拒绝，备份包含核心组与 SaaS 扩展。
9. 桌面、Web 的底栏“+”、右键/键盘编辑、状态标识和账号批量移动均有回归测试。
