# 异常请求结果提示与托盘支持设计

## 目标

为账号列表补充导致账号进入异常或冷却状态的上游请求结果查看能力，并为桌面应用增加托盘图标，使关闭主窗口默认隐藏到托盘而不是退出进程。

## 范围

### 账号异常与冷却详情

- 在 `route_credentials` 中新增可空字段，保存最近一次导致失败状态的上游响应内容。
- 保存内容限制最大长度，避免异常响应无限增长；无法解码为 UTF-8 时不保存响应内容，但仍保留现有失败消息。
- HTTP 错误、响应语义失败、响应转换失败等拥有响应体的失败路径保存响应内容。
- 连接失败、请求构建失败、刷新令牌失败等无响应体路径只保存失败类型和消息。
- 账号列表的“异常”和“冷却至”标签在存在响应内容时提供可悬停、可聚焦的详情浮层，显示失败类型、失败消息和格式化后的响应内容。
- 没有响应内容时保持现有状态标签，不显示空浮层。

### 托盘行为

- 使用现有 `src-tauri/icons/32x32.png` 创建托盘图标。
- 托盘菜单包含“显示主窗口”和“退出 AI Switch”。
- 点击托盘图标显示并聚焦主窗口；右键使用托盘菜单。
- 主窗口关闭事件默认阻止退出并隐藏窗口。
- 通过托盘“退出 AI Switch”设置退出标记后真正结束进程，避免被关闭事件再次隐藏。
- macOS 使用模板图标配置，Windows/Linux 使用同一应用图标。

## 数据流

1. 路由代理收到上游响应并判定失败。
2. 失败记录函数将失败类型、失败消息和可用响应体交给账号仓库。
3. 账号仓库截断并保存响应内容到 `last_failure_response_json`。
4. 账号列表 API 读取该字段并序列化给前端。
5. 前端在状态/冷却标签附近渲染响应详情浮层。

恢复成功或显式测试恢复账号时，同时清除失败响应字段，避免展示过期响应。

## 错误处理与安全边界

- 响应内容按字符长度截断，保存前去除首尾空白。
- 前端优先格式化合法 JSON；非 JSON 内容按原文显示。
- 浮层限制最大宽高并允许滚动，不改变账号行布局。
- 不保存请求头、API Key、请求体或完整上游 URL，只保存响应体。
- 托盘初始化失败应让应用启动失败并返回 Tauri setup 错误，而不是静默运行在无托盘状态。

## 验证标准

- Rust 仓库测试覆盖响应字段的保存、读取和恢复清除。
- 前端测试覆盖异常标签浮层显示 JSON、冷却标签浮层显示 JSON、无响应内容不显示浮层。
- `pnpm typecheck`、`pnpm test:run`、`pnpm build`、`pnpm rust:check` 全部通过。
- `tauri.conf.json` 能被 Tauri 构建解析，托盘图标路径存在。
