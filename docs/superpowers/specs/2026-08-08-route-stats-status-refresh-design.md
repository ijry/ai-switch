# 统计请求展示、分页与账号状态刷新设计

## 目标

修复统计请求列表的 Token 列布局和模型显示，保证统计分页切换真实生效，并让算力池账号因代理请求失败发生异常、冷却或撤销时实时刷新账号界面。同时确认新增账号字段对旧数据库的升级兼容性。

## 已确认范围

- Token 合并只作用于“统计”视图中的请求列表行。
- 顶部统计汇总卡片继续保留现有请求、输入 Token、输出 Token、缓存 Token、Token 总计和费用卡片。
- 请求列表将输入/输出/缓存三列合并为一个“Token”列。
- “Token”列直接显示当前统计口径的总 Token；鼠标悬停显示输入、输出、缓存三项明细。
- 请求模型列显示请求模型；当发生模型映射且上下游模型不同时显示 `请求模型->上游模型`。
- 旧统计记录没有新增模型元数据时显示 `-`，不影响历史数据读取。

## 根因

### 1. 数据库升级

`202608080002_route_credential_priority_concurrency.sql` 使用 `ALTER TABLE ... ADD COLUMN` 追加 `route_priority` 和 `max_concurrency`，并设置默认值 `3` 和 `1`。应用启动时通过 `sqlx::migrate!("./migrations")` 自动执行未应用迁移，因此旧版本数据库升级到当前版本时会保留原账号和池成员关系，并自动填充新字段。

这保证“旧数据库升级到新版本”，不把“新数据库降级后继续由旧版本运行”作为兼容目标。新版本新增的迁移记录也不应被旧版本回滚或覆盖。

### 2. 统计模型信息缺失

当前请求事件只保存通用 `metadata_json`，代理元数据没有统一写入请求模型和上游模型。前端只能显示路径、状态和 Token 明细，无法知道请求是否经过模型映射。

### 3. 分页状态竞争

请求分页使用包含页码的 TanStack Query key，但切换 key 后没有保留上一页统计数据。组件在请求新页期间根据空数据计算出 `requestPageCount = 1`，页码控件会短暂退回或被禁用，造成点击下一页无效的表现。现有测试只检查 `getRoutePool` 收到了页码参数，没有断言请求列表和页码显示已经切换。

### 4. 账号状态事件缺失

前端目前只订阅 `route-credential-activity`，该事件只更新活动并发数。代理调用 `record_semantic_failure`、`update_status`、`record_transient_failure` 和 `clear_transient_failure` 后没有通知账号页面刷新，导致数据库状态已变化但 Query cache 仍显示旧状态。

## 设计

### 1. 统计请求元数据

代理在一次请求开始时提取入站请求模型 `requested_model`。构建上游请求后，从最终发送的请求体读取 `upstream_model`；如果模型位于协议转换的路径中，则使用当前协议桥接生成的目标模型。

所有代理请求事件的 `metadata_json` 统一增加：

```json
{
  "requested_model": "gpt-5.6-sol",
  "upstream_model": "sol-upstream"
}
```

没有映射时两个值相同；无法从旧请求或非 JSON 请求中获取时字段可以缺失。

前端解析元数据时按以下规则生成列表显示值：

1. `requested_model` 和 `upstream_model` 都存在且不同：显示 `requested_model->upstream_model`。
2. 只有一个存在：显示存在的模型。
3. 都不存在：显示 `-`。

模型列使用 `truncate`，完整值通过 `title` 和请求详情中的 `metadata_json` 保留。

### 2. 请求列表 Token 列

请求列表删除独立的输入、输出、缓存三列，新增一个“Token”列：

- 主值为 `input_tokens + output_tokens`，沿用当前 `token_count` 的统计口径，不把缓存 Token 重复计入总值。
- 任一输入/输出值存在时显示总值；两者都缺失时显示 `-`。
- 鼠标悬停显示输入、输出、缓存 Token 三项。
- 无障碍文本包含三项明细，不能只依赖颜色或视觉 tooltip。

顶部汇总卡片不改变。

### 3. 统计分页

统计 Query 增加 `placeholderData: keepPreviousData`，页码变化时保留上一页数据直到新页请求完成。页码计算使用当前数据；新页响应返回后更新 `request_page`、请求总数和请求行。

分页按钮在请求期间保留可用状态但避免重复提交同一页请求；请求失败时继续显示上一页，并在现有反馈区域显示错误。切换统计周期时仍将页码重置为 `1`。

测试必须同时断言：

- 点击下一页调用 `getRoutePool(..., 2, 20)`。
- 新页响应后页码显示为 `请求 2/3`。
- 新页请求行替换上一页行。
- 切换统计周期重置为第一页。

### 4. 账号状态变更事件

复用当前运行时事件出口，在 `RouteCredentialActivityRegistry` 上增加状态变更事件发送能力，避免为 Tauri 和 Web 分别维护两套事件桥：

- 事件名：`route-credential-status`
- 载荷：

```json
{
  "platform": "codex",
  "credential_id": "credential-id"
}
```

事件不携带完整账号对象，前端收到后重新读取数据库，确保状态、冷却时间、失败原因和失败响应 JSON 同步更新。

以下代理状态/可用性写入完成后发送事件：

- 记录瞬时失败和冷却信息；
- 清除瞬时失败；
- 记录语义失败并设置 `error`；
- 设置 `revoked`；
- 自动模型测试中的恢复、语义失败和永久失败。

数据库更新失败时不发送事件。事件发送失败不影响原请求结果，也不回滚已完成的数据库写入。

前端订阅事件后：

1. 过滤非当前平台事件；
2. 失效当前平台的账号分页 Query、全量账号 Query、算力池 Query；
3. 保留当前账号页和统计页状态，让 TanStack Query 重新加载；
4. 与现有活动事件订阅互不覆盖。

## 兼容性

- 不新增统计数据库列，模型信息写入已有 `metadata_json`。
- 旧 `usage_events` 记录保持可读，模型列显示 `-`。
- 旧数据库升级由现有迁移机制自动完成，新账号字段默认值不变。
- 不改变统计汇总口径、状态判定规则和路由选择规则。

## 测试策略

### Rust

- 验证迁移后的旧账号可读取 `route_priority=3`、`max_concurrency=1`。
- 验证代理成功、失败和映射请求元数据包含请求模型与上游模型。
- 验证状态事件在冷却、恢复、语义失败和撤销路径发送。
- 验证状态写入失败时不发送事件。
- 保留现有统计 Token 汇总和分页 repository 测试。

### 前端

- 验证请求行只有一个 Token 列。
- 验证 Token 主值和悬停明细。
- 验证无映射显示单模型，映射显示 `A->B`，旧元数据显示 `-`。
- 验证点击下一页后列表内容和页码都切换。
- 验证收到 `route-credential-status` 后刷新账号和算力池 Query。

## 不采用的方案

- 不为模型信息新增独立数据库列，避免迁移历史记录和统计查询复杂化。
- 不在前端收到活动事件后无条件刷新账号列表，避免每个请求产生额外数据库查询。
- 不仅通过定时轮询刷新账号状态，避免最多等待一个轮询周期且无法覆盖独立 Web 客户端的即时状态变化。
