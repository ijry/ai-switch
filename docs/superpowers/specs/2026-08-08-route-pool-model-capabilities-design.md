# 算力池模型能力匹配与展示设计

## 背景

当前算力池按账号轮询，不读取请求模型判断账号是否具备对应能力。API 账号的 `model_mappings` 只在选中账号后用于把本地模型名改写成上游模型名，因此一个只支持有限模型的上游账号可能被错误选中，直到上游返回模型不存在错误后才重试下一个账号。

同时，算力池的 `/models` 目前只返回已配置映射的本地模型别名，未配置映射的透传账号没有明确的客户端基线模型列表；账号列表也不展示每个账号支持的本地模型别名，用户难以判断池内模型覆盖范围。

## 目标

1. 让算力池在发送请求前按请求模型过滤账号，避免把有限模型请求发给不匹配账号。
2. 保留无映射账号的现有透传语义：无映射账号视为通配账号，可承接任意请求模型。
3. 让 `/models` 返回与实际匹配规则一致的客户端模型集合。
4. 在模型映射编辑器中提示有限模型上游的配置风险。
5. 在账号列表中以标签展示本地模型别名，并通过 popover 查看完整映射。
6. 不新增数据库字段，不改变既有 `model_mappings` JSON 格式，不要求迁移历史账号。

## 非目标

- 不通过每次 `/models` 请求实时访问所有上游的模型列表。
- 不把无映射账号强制改造成必须配置映射的账号。
- 不修改既有 `from -> to` 请求改写、协议桥接、失败重试和游标顺序语义。
- 不为 Gemini 增加新的协议选择下拉框。

## 统一模型能力规则

新增一个可被请求过滤和 `/models` 共用的纯模型能力模块，避免两个入口各自维护不同规则。模块负责：

- 从请求 JSON 顶层读取非空字符串字段 `model`。
- 解析账号配置中的 `model_mappings`，过滤空值和 `upstream-model` 占位映射。
- 判断账号是否支持请求模型。
- 聚合对外可见的客户端模型 ID。

账号支持判断：

| 账号配置 | 请求有 `model` | 请求没有 `model` |
| --- | --- | --- |
| `model_mappings` 为空 | 支持，视为通配账号 | 支持 |
| `model_mappings` 非空 | 仅当某条 `from` 命中时支持 | 支持 |

模型命中沿用现有规则：普通平台使用去除首尾空白后的精确匹配；Claude 继续将 `[1m]` 后缀归一化后匹配，并由 `supports_1m` 决定是否额外公开 1M 别名。

## 请求路由

在 `forward_request` 读取请求体后、读取池游标前执行模型过滤。`/models` 仍走独立的 GET 快路径，不读取请求体。

处理顺序：

1. 解析平台和路由能力规则。
2. `/models` 请求走模型列表逻辑。
3. 读取普通请求体，提取 `model`。
4. 查询池账号并按平台能力过滤。
5. 如果请求带模型且过滤结果为空，返回稳定错误码 `route_pool.model_unmatched`，错误详情包含平台和请求模型，不包含密钥。
6. 对剩余账号读取游标，按现有顺序重试。
7. 选中账号后继续执行现有映射改写、协议桥接、上游请求和响应转换。

请求体不是有效 JSON、没有 `model` 或 `model` 为空时，不做模型过滤，保持现有全池轮询行为。

## 对外模型列表

`/models` 返回客户端可请求的模型 ID 并集，使用大小写不敏感去重，固定模型先出现在列表中，映射别名按池内账号顺序追加。

平台固定基线：

- Codex：`gpt-5.6-sol`、`gpt-5.6-terra`、`gpt-5.6-luna`、`gpt-5.5`。
- Claude：现有角色别名 `claude-sonnet-5`、`claude-opus-4-8`、`claude-fable-5`、`claude-haiku-4-5`。
- Gemini：现有默认模型 `gemini-2.5-flash`。
- Grok：现有默认模型 `grok-4.5`。

列表规则：

- 池内存在至少一个无映射账号时，加入当前平台固定基线。
- 无论是否存在无映射账号，都加入所有有效映射的 `from`。
- 池内全部账号都有映射时，不额外加入固定基线，只返回映射别名集合。
- Claude 的 `supports_1m = true` 为对应 Claude 别名额外加入 `[1m]` 版本。
- 没有账号或没有有效映射时返回空 `data`，不虚构上游模型。

该规则保证：当池只包含有限映射账号时，列表不会宣称支持没有候选账号的模型；当池包含透传账号时，固定基线表达本地入口的默认可请求模型集合。

## 前端模型映射提示

在 API 账号创建和编辑共用的 `ModelMappingsEditor` 中，在现有说明文字上方增加提示：

- 无映射时使用警示样式：说明如果上游只支持有限模型，建议先获取上游模型列表并配置 `from -> to`；配置后算力池只会把该账号匹配到这些本地别名。
- 有映射时使用普通说明：显示当前账号仅按已配置的本地别名参与模型匹配。
- 提示不阻止保存空映射，因为空映射仍然是合法的通配账号语义。

提示只出现在 API 模型映射编辑区域，不改变官方账号流程或 Gemini 的协议选择下拉；Gemini API 账号进入模型映射编辑器时同样遵循上述通用提示规则。

## 账号列表模型标签

账号行从 `config_json.model_mappings` 解析模型映射：

- 映射为空时显示 `模型通配` 标签。
- 映射为 1 至 3 条时，直接显示每条映射的 `from` 别名标签。
- 映射超过 3 条时显示前 3 条标签和 `+N` 按钮；`N` 是剩余映射数量。
- 点击 `+N` 打开当前账号的 popover，列出完整的 `from -> to` 映射。
- popover 中显示可选的 `label`，Claude 1M 映射显示 `[1m]` 标记。
- 长模型名在标签中截断，并通过 `title` 保留完整值。
- popover 支持点击外部关闭、Escape 关闭、`aria-expanded` 和键盘操作。

模型标签不改变账号现有排序、筛选、拖拽、批量操作和右侧操作按钮布局。

## 数据流与边界

```text
本地请求
  -> 解析平台和 model
  -> 读取池账号
  -> 无映射通配 / 有映射命中过滤
  -> 选中账号
  -> from -> to 改写
  -> 协议桥接
  -> 上游请求
```

```text
/models
  -> 读取池账号
  -> 固定基线（仅存在通配账号时）
  -> 合并所有映射 from
  -> Claude 1M 展开
  -> 大小写不敏感去重
  -> 返回 OpenAI-compatible list
```

所有新逻辑只读取现有 `config_json`，不改变数据库 schema。模型能力模块不得读取或输出 `secret_payload_json`。

## 测试设计

Rust 单测覆盖：

1. 空映射账号匹配任意模型。
2. 有映射账号命中和不命中。
3. 混合通配与有限映射账号时只返回正确候选。
4. 无候选时返回 `route_pool.model_unmatched`。
5. Codex 固定四模型与映射别名合并、大小写去重。
6. 全部账号有映射时不返回未被映射的固定基线。
7. Claude `[1m]` 列表展开和命中规则。

前端单测覆盖：

1. 空映射提示有限模型配置风险。
2. 有映射提示已配置别名数量。
3. 账号行显示 1、3、超过 3 个模型标签。
4. `+N` popover 展示完整 `from -> to` 和关闭行为。
5. 无映射账号显示 `模型通配`。
