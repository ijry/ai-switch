# 账号池分段视图设计

## 目标

在账号页面增加分段器，按当前平台切换“已入池”“未入池”“统计”三种视图。账号视图必须继续支持后端分页、批次筛选和排序，且加入/移出算力池操作必须与当前分段一致。

## 交互

- 默认分段为“已入池”；切换平台后重置为“已入池”。
- “已入池”只显示当前平台已加入算力池的账号，显示加入池相关的移出操作。
- “未入池”只显示当前平台未加入算力池的账号，显示加入算力池操作。
- “统计”显示现有请求统计面板，不显示账号选择、账号排序或加入/移出操作。
- 批次筛选、分页大小和账号排序仅作用于账号分段；切换分段时页码重置为第一页并清空选择。

## 数据与接口

- 为账号分页请求增加池成员条件：`in_pool`、`out_of_pool`。
- 后端分页查询使用当前平台的 `route_pool_members` 关系进行 `EXISTS` / `NOT EXISTS` 过滤，并据此计算总数、页边界和筛选结果。
- 重排接口接收同样的池成员条件，仅重排当前分段内的账号槽位，保持其他账号的相对位置。
- 前端继续使用现有算力池查询获取成员 ID，并在 mutation 成功后刷新账号分页和算力池状态。

## 操作约束

- 已入池分段的批量操作只允许移出；未入池分段的批量操作只允许加入。
- 行内操作与批量操作使用相同的分段条件，避免在当前视图中出现反向操作。
- 统计分段不触发账号分页请求，不保留账号选择状态。

## 测试

- Rust repository 测试覆盖池内/池外分页、空页和总数。
- Rust reorder 测试覆盖池成员条件下的跨页邻居与过滤槽位替换。
- `AccountsScreen` 测试覆盖分段切换、操作按钮方向、统计视图和页码重置。

## 非目标

- 不改变算力池成员存储结构、统计口径或现有批次筛选语义。
- 不增加“全部账号”分段；需要查看全部账号时仍通过未入池/已入池视图分别操作。
