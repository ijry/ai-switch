# 中转站

这一页收录**经过实测可用**的第三方 AI 中转站，以及它们在 AI Switch 里怎么接。

::: info 关于页面内的链接
下面每张卡片的注册按钮都是**邀请链接**（含 `aff` 参数）。通过它注册，你会拿到卡片里写的新用户额度，同时本项目作者也会获得对应的邀请额度。如果你不希望产生返利，直接访问对应站点的官网注册即可，不影响你的使用。
:::

::: warning 先读这一段
这些站点**不是 AI Switch 运营的，也不受本项目控制**。收录只代表某个时间点实测能用，不构成任何形式的担保或推荐承诺：

- **额度、倍率、邀请规则随时会变**，站点也可能限流、跑路或直接关停。卡片上标了实测日期，超过三个月请以站点自己的公告为准。
- **中转站能看到你发过去的全部请求内容**。涉密代码、生产环境凭据、客户数据不要经第三方中转，这跟用哪一家无关。
- **公益站按「随时可能停」来规划**。别把它当主力，更别让它成为唯一的路。
- 出问题请找站点自己的支持渠道，本项目无法代为处理充值、退款或封号申诉。
:::

## 在 AI Switch 里怎么接

拿到中转站的 base URL 和 API key 之后，流程和接任何一个 API 账号没有区别：

1. 打开**账号**页，选好平台（Codex / Claude Code / …），新建一个 API 账号。
2. 填 **base URL** 与 **API key**。
3. 选**上游协议**——这一步决定桥接走哪条链路，填错了会直接报协议错误。中转站通常会在文档里写明它兼容哪种接口格式：
   - 兼容 OpenAI Chat Completions → `openai`
   - 兼容 OpenAI Responses → `openai-responses`
   - 兼容 Anthropic Messages → `anthropic`
   - 兼容 Gemini generateContent → `gemini`
4. 保存后点一次[模型连通性测试](/guide/model-test)，确认真能打通再入池。

::: tip 拉不到模型列表就手填
有些中转站不提供模型列表接口，或者接口返回的名字和实际可用的对不上。AI Switch 允许手动填模型名——直接把中转站文档里的模型 ID 抄进去即可，不影响转发。上面卡片里标注了需要手填的站点和具体模型名。
:::

### 多个中转站怎么配合

中转站的稳定性普遍不如官方，所以更值得用[算力池](/guide/accounts)来兜：

- 把主力号的**路由优先级**设成 1，中转站设 3。主力可用时流量全走主力，主力挂了自动降级到中转站。
- 几个中转账号设**同一个优先级**，池子会在它们之间轮转，摊平负载。
- 中转站限流敏感，**最大并发数保持默认 1**，别调高。
- 按天重置额度的站点，[自动恢复](/guide/reliability)设成「每日定时」，时刻放在重置之后一点；限流窗口不确定的用「探活恢复」。

### 模型名不一致就做映射

中转站的模型 ID 常常和客户端请求的名字不一样。这种情况不用改 CLI，在账号的**模型映射**里把客户端模型名映射到上游真实模型名即可。请求列表里会显示成 `请求模型->上游模型`，一眼能看出映射生效了。
